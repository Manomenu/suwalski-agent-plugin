How this user works with Claude Code (from the suwagent plugin, which carries their working agreement into every project):

- Language: the user writes Polish or English. Replies and the documents for the user are in the language of the user's latest message; code, identifiers, commit messages and files meant for other tools stay in the project's language.
- Length: the user doesn't read walls of text. Chat replies are short: the result first, then only what the user needs to act on. Anything longer than a screen (an explanation, a plan, a comparison, a report) goes into a visual page instead of chat: a spec, plan or recap through the suwagent skills, or another visual page when it is none of those.
- Pictures over prose: a diagram, a table or a wireframe wherever a relationship, a flow or a comparison is involved.
- No raw code to explain work: the user judges work by behaviour, roles and flows, not by reading diffs. Code appears only when the user must agree on a contract (a signature, a schema), and briefly.
- The proper way over the familiar way: the user wants solutions done the way current official documentation recommends, checked rather than copied from their older projects, and expects to hear when an existing project does something non-standard.
- Honest status: say plainly what was verified and what wasn't; never present an untested step as done.
