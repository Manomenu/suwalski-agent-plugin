Recap

TL;DR

🟡 Repo jest teraz marketplace'em Claude Code z jednym pluginem suwagent. Plugin daje trzy skille: /suwagent:visual-spec, /suwagent:visual-plan i /suwagent:visual-recap. Każdy pisze samodzielną stronę HTML w docs/visual/<data>-<slug>/, a z niej wracasz do agenta z feedbackiem. Hook SessionStart mówi agentowi, żeby przy większych zmianach proponował spec → plan → recap.

Struktura jest zgodna z oficjalną dokumentacją i claude plugin validate przechodzi. Do sprawdzenia zostało: instalacja z GitHuba i test w żywej sesji. Ta strona jest pierwszym recapem zrobionym tym pluginem.

Czy robi to, o co prosiłeś

  • Plugin zrobiony „zgodnie ze sztuką”, według oficjalnej dokumentacji, a nie na wzór moich wcześniejszych pluginów marketplace w korzeniu repo, plugin w plugins/suwagent/, ścieżki przez ${CLAUDE_PLUGIN_ROOT}, zero ..; claude plugin validate . → „Validation passed with warnings” (jedyne ostrzeżenie: brak version, celowo)
  • Są skille visual-spec, visual-plan i visual-recap plugins/suwagent/skills/*/SKILL.md, każdy poniżej 100 linii, wspólne zasady w shared/authoring.md
  • Domyślna instrukcja: przy większej zmianie proponuj spec, potem plan, a po robocie recap hook działa uruchomiony ręcznie: 1050 znaków na stdout, 0 przy wyłączonej opcji. Jeszcze nie sprawdzone w sesji Claude Code po instalacji
  • Wiadomo, jak działają aktualizacje bez pola version każdy commit to nowa wersja; auto-update włączasz w /plugin → Marketplaces (dla zewnętrznych marketplace'ów jest domyślnie wyłączony); opisane w README
  • Strony czyta się wizualnie, recap bez surowego kodu: diagramy, role elementów, scenariusz krok po kroku, jasny i ciemny motyw ta strona wyrenderowana w headless Firefoksie, zrzuty w obu motywach; vdoc.py check → OK
  • Feedback wraca do agenta ze strony formularz, komentarze do sekcji i przycisk „Kopiuj feedback” są zrobione; kopiowanie do schowka nie było klikane w prawdziwej przeglądarce

Czym to się różni od BuilderIO/skills

BuilderIO

Plany i recapy to MDX publikowany do hostowanej aplikacji Plans (plan.agent-native.com) przez serwer MCP, z kontem, komentarzami w aplikacji i instalatorem npx. Bez połączenia skill się zatrzymuje.

suwagent

Lokalny plik HTML z szablonu: zero kont i usług, działa offline (diagramy pokazują wtedy źródło). Feedback idzie przez schowek do czatu. Dokument jest plikiem w repo, więc można go wersjonować. Recap jest bardziej abstrakcyjny niż u nich: bez diffów, za to role elementów i przebieg scenariusza.

Wziąłem z BuilderIO dyscyplinę treści: TL;DR na początku, konkret przed abstrakcją, decyzje wprost, jeden formularz otwartych pytań, recap całej pracy, a nie tylko ostatniego kroku, recap sprawdzany ze specem. Ich infrastruktury nie wziąłem. Doszedł visual-spec, którego oni nie mają: co i dlaczego przed jak. Recap sprawdza kryteria akceptacji ze specu.

Jak to działa

Elementy i ich role

Hook SessionStart

Na starcie sesji (także po /clear i kompakcji) dopisuje agentowi krótką umowę roboczą: przy większej zmianie zaproponuj spec, potem plan, a po robocie recap; drobiazgi rób od razu. W pluginie to zastępuje „domyślny CLAUDE.md”, bo plugin CLAUDE.md nie ładuje.

wyłączasz w /plugin → suwagent → Configure

Trzy skille

Każdy opisuje, jakie sekcje ma dokument i jakie zasady obowiązują: spec bez kodu i plików, plan tylko do zatwierdzenia (zero zmian w kodzie przed akceptacją), recap bez diffów i z dowodami. Claude sięga po nie sam, gdy opis pasuje do zadania, albo Ty wpisujesz komendę.

Wspólne zasady i katalog bloków

authoring.md ustala, gdzie trafia plik, jakie są kroki, jak działa pętla feedbacku i jaki jest poziom jakości (TL;DR na górze, konkret przed abstrakcją, jedno miejsce na pytania). components.md zawiera gotowe snippety bloków, więc agent nie wymyśla wyglądu.

Szablon strony

Jeden plik z całym wyglądem i zachowaniem: jasny i ciemny motyw, spis treści, diagramy, wireframe'y, formularz pytań, komentarz do każdej sekcji i pasek „Zatwierdzam / Poprawki / Kopiuj feedback”. Agent pisze tylko treść.

vdoc.py

Pomocnik agenta. new tworzy stronę z szablonu, check wyłapuje błędy, które zepsułyby stronę (pusta treść, zły JSON adnotacji, brak sekcji typowych dla danego dokumentu), a open otwiera ją w przeglądarce.

Marketplace

Repo jest katalogiem pluginów. Instalujesz z GitHuba jedną komendą, a aktualizacje przychodzą z każdym pushem, jeśli włączysz auto-update.

Co się dzieje, gdy prosisz o większą zmianę

  1. Opisujesz zadanie. Agent ma w kontekście umowę z hooka, więc zamiast od razu kodować proponuje w jednym zdaniu visual-spec.

  2. Spec trafia do docs/visual/2026-…-slug/spec.html i otwiera się w przeglądarce. W czacie dostajesz 3–5 linii, a nie ścianę tekstu.

  3. Na stronie odpowiadasz na pytania, komentujesz sekcje i klikasz „Zatwierdzam” albo „Poprawki”, a potem „Kopiuj feedback”. Wklejasz to w czat, agent poprawia ten sam plik i otwiera go ponownie.

  4. Po akceptacji speca to samo dzieje się z plan.html w tym samym folderze. Kod powstaje dopiero po zatwierdzeniu planu.

  5. Po robocie recap.html odhacza kryteria ze speca z dowodami, wyjaśnia rolami i diagramami, jak to działa, i wskazuje, gdzie patrzeć uważnie, bez pokazywania kodu.

Przy drobnej zmianie (literówka, poprawka w jednej linii) agent niczego nie proponuje. Gdy raz odmówisz, nie proponuje ponownie w tym samym zadaniu.

Weryfikacja

claude plugin validate . (Claude Code 2.1.310): marketplace i plugin przechodzą. Jedno ostrzeżenie: brak version, celowo.

Hook uruchomiony ręcznie: 1050 znaków umowy na stdout (limit kontekstu z hooka to 10 000), a przy CLAUDE_PLUGIN_OPTION_SUGGEST_VISUAL_DOCS=false nic.

Ta strona: vdoc.py new → treść → check (OK) → render w headless Firefoksie w jasnym i ciemnym motywie.

Niesprawdzone: instalacja z GitHuba przez /plugin marketplace add (repo nie jest jeszcze wypchnięte), wstrzyknięcie hooka w żywej sesji, kliknięcie „Kopiuj feedback” w prawdziwej przeglądarce oraz to, czy Claude sam zaproponuje skille przy większej zmianie.

Gdzie patrzeć uważnie

MiejsceDlaczego
shared/template.html renderDiagramsMermaid ładowany jako moduł ESM z jsDelivr na stronie file://. Działa w Firefoksie. Chrome też powinien (CDN wysyła ACAO *), ale tego nie sprawdzałem.

Otwarte pytania

Nazwa pluginu

Nazwa jest prefiksem komend (/suwagent:visual-plan). Po publikacji zmiana psuje instalacje, teraz jest darmowa.

Czy dokumenty z docs/visual/ mają trafiać do gita?

Commitowane zostawiają historię decyzji przy kodzie. Ignorowane nie śmiecą w diffach.

Wersjonowanie pluginu

Bez version każdy push od razu trafia do Ciebie (przy auto-update). Z version trzeba ją podbijać przy każdym wydaniu.
